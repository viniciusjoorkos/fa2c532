## ✅ Checklist de Migração

### PASSO 1 — Criar novo projeto Supabase

- [ ] Acesse `supabase.com/dashboard` com sua nova conta
- [ ] Clique em **New Project**
- [ ] Preencha:
  - **Name:** RZ Trader Studio (ou qualquer nome)
  - **Database Password:** crie uma senha forte e anote
  - **Region:** South America (São Paulo) — mais próximo do Brasil
- [ ] Aguarde ~2 minutos para o projeto inicializar
- [ ] Acesse **Project Settings → API** e anote:
  - `Project URL` → será o novo `VITE_SUPABASE_URL`
  - `anon public` key → será o novo `VITE_SUPABASE_PUBLISHABLE_KEY`
  - `Project ID` → será o novo `VITE_SUPABASE_PROJECT_ID`

---

### PASSO 2 — Executar as migrations (ordem obrigatória)

Acesse **SQL Editor** no novo projeto e execute cada arquivo abaixo na ordem:

> **Como executar:** Abra o arquivo → copie o conteúdo → cole no SQL Editor → clique em **Run**

| # | Arquivo | O que faz |
|---|---------|-----------|
| 1 | `supabase/migrations/20260430051450_2f7e1606-2d1d-4c3f-b72e-5951be40e926.sql` | Schema principal: todas as tabelas, políticas RLS, triggers e funções |
| 2 | `supabase/migrations/20260430051507_1340b686-b706-4f3a-a12e-8a85ef27c917.sql` | Complemento do schema inicial |
| 3 | `supabase/migrations/20260502_melhorias_v2.sql` | Melhorias v2: notificações, scores, is_gold |
| 4 | `supabase/migrations/20260502_planos_v2_parte1.sql` | Atualização de planos parte 1 |
| 5 | `supabase/migrations/20260502_planos_v2_parte2.sql` | Atualização de planos parte 2 |
| 6 | `supabase/migrations/20260502_site_settings.sql` | Tabela de configurações do site (admin) |
| 7 | `supabase/migrations/20260502_v3_chat_sessions.sql` | Chat público e mensagens em tempo real |
| 8 | `supabase/migrations/20260502_v4_enable_realtime.sql` | Habilitar Realtime nas tabelas |

> ⚠️ **Atenção:** Execute na ordem exata. Se algum der erro, leia a mensagem — pode ser que uma extensão precise ser habilitada (ex: `uuid-ossp` já vem ativa no Supabase por padrão).

### PASSO 3 — Configurar Authentication

No novo projeto, vá em **Authentication → Providers → Email** e configure:

| Configuração | Valor |
|---|---|
| Enable Email Provider | ✅ ON |
| **Confirm email** | ❌ **OFF** ← DESLIGAR AQUI |
| Secure email change | à sua escolha |

Depois vá em **Authentication → URL Configuration**:

| Campo | Valor |
|---|---|
| Site URL | `https://seudominio.com` |
| Redirect URLs | `https://seudominio.com/**` |

> 💡 Se ainda estiver em desenvolvimento local, use `http://localhost:5173` e `http://localhost:5173/**`

## 🔧 Configuração de E-mail (opcional mas recomendado)

Para e-mails de recuperação de senha funcionarem corretamente, configure SMTP próprio:

**Serviço recomendado:** [Resend](https://resend.com) — gratuito até 3.000 e-mails/mês

| Campo | Valor |
|---|---|
| Host | `smtp.resend.com` |
| Port | `465` |
| Username | `resend` |
| Password | `re_SUA_API_KEY_DO_RESEND` |
| Sender name | `RZ Trader Studio` |
| Sender email | `noreply@seudominio.com` |

Configure em: **Authentication → SMTP Settings → Enable Custom SMTP**

## 🆘 Se algo der errado

| Problema | Solução |
|---|---|
| Erro ao executar migration | Leia a mensagem de erro no SQL Editor — geralmente é ordem errada |
| Site não conecta ao banco | Verifique se `.env` foi salvo e reinicie `npm run dev` |
| Usuário não virou admin | Execute no SQL Editor: `SELECT * FROM user_roles;` para verificar |
| Realtime não funciona | Execute a migration 8 novamente |
| E-mail de recuperação não chega | Configure SMTP próprio (Resend) — veja seção acima |
